## 二、核心数据模型（字段级定义）

### 2.1 用户 User
聚合自 `mock/user-profile-db.js → getUserProfile()`

```
basicInfo: {
  nickname, avatar, gender, birthday, age,
  zodiac,        // 星座（由生日推导，如"摩羯"）
  fiveElements   // 纳音五行（由年生推导）
}
```

### 2.2 氧系人格 Personality（mock/personality-db.js）
六种：`explorer`(氧气探险家) / `thinker`(深氧思考者) / `healer`(轻氧治愈者) / `energetic`(活力氧人) / `slower`(慢氧生活家) / `sensitive`(高氧敏感体)

```
personality: {
  id, name, icon, mbti, color, bgGradient,
  tags: [],          // 人格标签
  description,       // 人格描述
  destinations: [],  // 推荐目的地池
  sports: [],        // 适合运动池
  chargeWays: [],    // 充能方式池
  quote, vibe, zodiac, fiveElements
}
```

### 2.3 情绪/打卡记录 Record（utils/checkinService.js → record）
这是**最核心的表**，一次打卡生成一条：

```
record: {
  date,             // 日期(YYYY-MM-DD·toDateString)
  text,             // 用户输入文字（拍照打卡为"（拍照打卡）"）
  scene,            // 场景中文名：高原旅行/脑疲劳/运动恢复/银发陪伴
  emotionLabel,     // 情绪标签（开心/平静/放松/疲惫/焦虑/烦躁/低落/紧张/孤独）
  confidence,       // 情绪置信度 0-1
  insight,          // 情绪洞察文案
  regulationTip,    // 调节建议文案
  productHint,      // 产品提示文案
  personaLine,      // 人格话术
  energy,           // 氧气能量值 0-100
  keyword,          // 主关键词
  keywords: [],     // 关键词数组
  state,            // 状态类型（元气日/平稳日/待充电日等）
  suggestion,       // 健康建议文案
  indexes: {          // 五项能量指数 0-100
    calmPower, active, think, stable, energy
  },
  faceMood,         // 拍照面部感知（happy/calm/tired）
  physicalTags: [], // 身心自选标签
  recipe: {           // 今日健康食谱推荐（详见2.7）
    ...
  }
}
```

### 2.4 现时氧气状态 State（utils/stateEngine.js）
由情绪 + 场景 + 人格 + mock面部 生成：

```
stateReport: {
  energy,           // 能量值 0-100
  emotion,          // 情绪
  keywords: [],     // 关键词
  state,            // 状态类型
  suggestion,       // 建议
  indexes: { calmPower, active, think, stable, energy },
  insight, personaLine, regulationTip, productHint
}
```

情绪 → 状态类型映射（STATE_TYPES）：
`开心→元气日 / 平静→平稳日 / 放松→松弛日 / 疲惫→待充电日 / 焦虑→波动日 / 烦躁→升温日 / 低落→低气压日 / 紧张→紧绷日 / 孤独→思念日`

### 2.5 场景健康方案 Scene（mock/health-scene-db.js）

## 三、前端 Service 层 → 后端 API 映射建议

当前 utils/ 下的 service 都是纯前端 mock，未来接后端时，**保持函数签名不变**，只替换内部实现：

| 前端service | 职责 | 对应后端API建议 |
|---|---|---|
| `checkinService.runCheckin()` | 打卡分析→生成记录 | `POST /api/checkin`（提交文本/照片+场景→返回 record） |
| `stateEngine.buildStateReport()` | 生成今日状态 | 由 checkin 接口客户端处理，或 `GET /api/state/today` |
| `emotionEngine.analyze()` | 关键词情绪分析 | **未来换真实AI**：`POST /api/emotion/analyze`（文本→情绪+置信度） |
| `faceApi.recognizeFace()` | 拍照面部感知 | 未来`POST /api/emotion/face`（图片→情绪） |
| `oxygenService.analyzeOxygen()` | 氧分析服务 | `POST /api/oxygen/analyze` |
| `chatEngine.reply()` | 数字人聊天 | `POST /api/chat`（支持AI对话） |
| `getUserProfile()` | 聚合用户画像 | `GET /api/user/profile` |
| `getPersonalityProduct()` | 人格→产品推荐 | `GET /api/personality/:type/product` |
| `matchProduct()` | 产品FAQ问答 | 并入 chat 接口 |
| 分享卡 sharePoster | 生成海报 | 前端canvas生成 + `GET /api/share/...`（可后接小程序码） |

## 四、给后端开发的关键提醒

1. **数据模型先定死**：用户/打卡记录/人格/偏好/成长 这些字段一旦定，前端所有页面都依赖，**尽量别大改**。
2. **接口通用化**：别做成和某个页面强绑定，做成可复用资源接口（如"提交一条记录""查用户画像"），前端重构页面不影响。
3. **情绪识别接口预留 AI 位**：现在是 mock，未来换真实 LLM/情绪模型时，`emotionEngine/faceApi` 的返回结构要保持兼容（emotionLabel/confidence）。
4. **照片处理**：打卡"氧气瞬间照片"当前只是本地路径占位，接后端后需考虑**图片上传（COS/OSS）+ 返回URL**。
5. **用户体系**：当前无登录，接后端需引入 **openid（微信）** 作为用户唯一标识。
6. **合规**：健康领域接口不返回"诊断性结论"，保持"趣味陪伴"文案；隐私字段（生日/照片/偏好）需脱敏与授权。
