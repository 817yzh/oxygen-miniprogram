# 氧氧宝 V1.0 页面信息架构重构原理（GPT 第二轮指导）
来源：涵姐与 GPT 讨论 V1.0 方向后，GPT 输出（2026-08-23）
本质：已从"UI优化"进入"产品设计逻辑"层面

## 核心原则
> **「主界面极简，深层内容丰富」**——第一层负责理解和行动，第二层负责探索和深入。

## 最关键的判断
- 氧氧宝最大的问题不是内容不够，而是**内容和用户接触的方式不对**
- 常见错误：功能多→全展示→用户懵。真实感受："好多东西……我该点哪里？"

## 一、重新定义页面信息层级
- 每个页面不问"我们有什么内容"，而问"**用户现在最需要完成什么**"
- **一级页面（第一眼）**：只放 1个核心状态 + 1个核心动作 + 2-3个辅助入口，不超过一个屏幕
- **二级页面（主动探索）**：数据详情/历史/分析/更多方案，经按钮/卡片/弹窗/抽屉/新页进入

## 二、首页具体例子
- 现在：氧气指数/情绪/活力/恢复/含氧感/趋势/建议/打卡/报告 全堆首页 → 像健康后台
- 改：第一屏 = 氧氧 + "今天氧气状态 82" + "稳定恢复中" + [开始今日调节] + 最多两个入口(查看更多状态→/今日建议→)
- "查看更多状态"→ 弹层显示详情（四维+近7天趋势）——**数据还在，但不打扰**

## 三、卡片="召唤式设计"（不做纯入口，做主动触发）
- 情绪日志：不放"情绪日志入口"，改氧氧主动说"今天还没记录心情，要告诉氧氧一句话吗？[记录一下]" → 点开浮层卡片
- 报告：达到条件才提醒"你的7日氧气报告生成啦🌱[查看报告]" → 报告作为奖励出现

## 四、三种交互大量使用
1. **Bottom Sheet（底部弹层）**：点氧气指数→底部升起"今日氧气分析（为什么是82？+建议）"，不跳页
2. **卡片展开**：今日建议默认一行→点开展开原因+推荐
3. **沉浸式页面（全屏）**：MBTI测试/氧气报告/AI聊天/音疗

## 五、从用户问题出发审视模块（最重要）
每个模块写：用户问题 → 氧氧宝解决方式 → 展示方式
- "我不知道自己为什么累" → 状态分析 → 首页一句话"今天你的恢复不足"+点击详情
- "压力大没人陪" → AI陪伴 → 聊天页
- "不知道适合什么健康方式" → 人格+场景推荐 → 氧气方案

## 六、视觉舒适度限制
1. 单屏：最多 1大视觉主体 + 3小信息点 + 1按钮
2. 卡片数：每页最多4张，超过就隐藏/收纳
3. 留白：氧气主题天然需要"呼吸感"，留白是品牌语言不是浪费

## 七、产品定位最终形态
不是"健康数据中心"，而是**"你的氧气空间"**：
- 首页=今天状态 / 氧氧=陪伴 / 探索=发现自己 / 充氧=获得方案 / 我的=记录成长
