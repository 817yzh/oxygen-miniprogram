## 第一轮（20:43 反馈）

### 问题 A：主包未使用 JS 文件（7 个）
- **报错：** `mock/age-profile-db.js`、`evidence-db.js`、`fun-db.js`、`personality-db.js`、`personality-product-map.js`、`scene-simulator-db.js`、`utils/checkinService.js`
- **根因排查：** 静态扫描全部 require，确认这 7 个文件**只在分包页面被引用**，主包无页面用到，却放在主包根目录 mock/、utils/ 下，白白占用主包体积
- **修复：** 迁移到对应分包目录
  - 纯数据 mock 文件 → mbti/mock、scene-detail/mock、scene-simulator/mock、share/mock
  - checkinService 依赖链复杂（依赖 faceApi/stateEngine/emotionEngine），评估后连带 faceApi、stateEngine 一起迁入 mbti/utils/
  - 公共模块（emotionEngine、health-scene-db，主包也用的）留根，改引用路径指回
- **⚠️ 踩坑：** 迁移脚本用正则改 require 路径时，`[^'"]*` 贪心吞掉了路径后的**闭合引号**，导致 10 处 require 出现 `require('x.js)` 缺引号语法错误
- **修复踩坑：** 人工(涵姐)在开发者工具发现 syntax error 并反馈 → AI 补回 10 处闭合引号，用 `node --check` 验证 8 个关键文件语法全过
- **教训：** ①改 require 用正则要防贪心吞引号；②迁移后必须 node --check + 跑回归；③改前先做全量备份可对照

### 问题 B：图片/音频超 200K
- **排查：** 本地 34 张图全 <200K、无本地音频；代码引用的是图床(GitHub oxygen-images)上的 CDN 图
- **定位：** 图床 18 个 CDN 图超 200K（最大 ip-final.png 1317K）
- **修复：** 用之前压缩好的版本替换并 push 回图床（commit fd654d2），18 图全部降到 26-107K
- **验证：** CDN HEAD 请求确认全部 <200K 生效

## 第二轮（20:54 反馈，复检）

### 问题 C：mock/recipe-db.js 又报"主包未使用"
- **根因：** 第一轮迁移 checkinService 时让 recipe-db.js 留根，但实测它**只被 checkinService(mbti分包) 引用**，主包无页面直接使用
- **修复：** recipe-db.js 迁到 pages/mbti/mock/，checkinService 引用改为同级 `../mock/recipe-db.js`；health-scene-db 因主包 report/home 在用，保留根目录
- **验证：** node --check 通过

### 问题 D：图片/音频超 200K（仍报）
- **深入排查：** CDN 全量 HEAD 验证 → 所有图片已 <200K，唯一 >200K 的是 `tech-principle.mp4`（15MB 远程视频）
- **判断：** 代码体检把 CDN 远程视频也计入"资源 >200K"检查
- **权衡：** 15MB 远程视频加载慢、现场演示易卡；V2 Demo 定位不依赖视频
- **修复：** product-center.wxml 的 video 卡片 → 静态技术原理图（workair-hero.png，50K）；清理 js 播放逻辑 + wxss 加静态图样式
- **验证：** 语法通过 + 主流程回归 PASS + 全项目无 >200K 资源

## 教训沉淀（写入团队知识）
1. 静态 require 扫描会误报"块注释里的示例代码"，要跳过注释行再解析
2. Windows + PowerShell 命令行拼中文/嵌套引号极易崩，多步操作一律写 python 脚本文件执行
3. 相对路径深度：pages/mbti/utils/ → 根必要上三级 `../../../`
4. 代码体检报"资源超限"要区分：本地打包资源 vs CDN 远程资源，远程视频虽不占包但可能被查到
